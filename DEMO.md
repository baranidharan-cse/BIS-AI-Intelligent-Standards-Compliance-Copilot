# Study Buddy — Judge Demo Script

**Total runtime: ~4 minutes**  
**Prerequisites:** backend running on `:8000`, frontend on `:5173`, database seeded with `python seed.py`

---

## Setup (before judges arrive, ~1 min)

```bash
# Terminal 1 — backend
cd backend && source .venv/bin/activate && python seed.py && uvicorn app.main:app --reload

# Terminal 2 — frontend
cd frontend && npm run dev
```

Open `http://localhost:5173` in Chrome (Chrome has the best Web Speech API support for the voice demo).

---

## Walk-Through Script

---

### 0:00 — Dashboard (30 s)

**[Navigate to Dashboard]**

> "This is Study Buddy — an AI study companion built on IBM watsonx.ai.
> The dashboard shows my learning at a glance: I've loaded 2 materials,
> have 12 concepts with partial mastery, and 5 revision tasks due today
> from the built-in spaced-repetition scheduler."

*Point to the stat cards. Note the "Due for Revision" number.*

> "Everything you see is live data from the API — let me show you how it works."

---

### 0:30 — Material Ingestion (45 s)

**[Navigate to My Materials → Paste Text tab]**

> "Study Buddy ingests any text — paste notes, a textbook excerpt, anything.
> The backend sends the text to IBM watsonx.ai via the `analyse_content()` method
> in `BaseLLMService`. The LLM extracts sections and atomic concepts — not just summaries."

*Show the two pre-seeded materials: Python Fundamentals (Ready) and Machine Learning Basics (Ready).*

> "We already have two materials loaded. The 'Ready' badge means the LLM pipeline
> has run: the text has been split into sections, and each section has had its
> key concepts extracted with definitions and examples."

*Click on the Python Fundamentals card to trigger navigation to Study.*

---

### 1:00 — Study Reader (30 s)

**[Navigate to Study → select Python Programming Fundamentals]**

> "In the Study page I can browse the material section by section.
> Each section is an accordion — let me open 'Control Flow'."

*Click the section. Expand it. Show concepts (if/elif/else, for Loop, while Loop).*

> "Each concept has a definition, explanation, and code examples — all extracted
> by the LLM. I can click 'Explain' to get a deeper explanation of any concept."

*Click 'Explain' on the 'for Loop' concept. Show the modal.*

---

### 1:30 — Learning Path (30 s)

**[Navigate to Learning Path → select Python Fundamentals → Generate]**

> "The learning path gives me a structured roadmap — Read, Practise, Reflect for each section,
> with time estimates. The first two steps are already marked complete from my earlier session."

*Point to the progress bar (showing 25%).*

*Click 'Mark Complete' on an in-progress step.*

> "Marking a step complete updates the progress bar in real time and feeds back into
> the mastery tracking."

---

### 2:00 — Quiz (45 s)

**[Navigate to Practice → select Python Fundamentals → set 5 questions → Generate Quiz]**

> "The quiz is generated by the LLM from the actual concepts in this material.
> Notice there are three question types: multiple choice, true/false, and short answer —
> all stored in the database with tracked attempts."

*Answer a few questions deliberately. Get some wrong.*

> "Let me submit this…"

*Click Submit Quiz. Show the results screen.*

> "I get per-question feedback: what I answered, what the correct answer was, and an explanation.
> The mastery score for each concept I got right has been updated in the database.
> If I keep practising, the app knows which concepts I struggle with."

---

### 2:45 — Revision Planner (30 s)

**[Navigate to Revision]**

> "This is the spaced-repetition scheduler — the core AI content-scheduling feature.
> It's not an LLM call; it's a real algorithm inspired by the SM-2 method.
> Review intervals are 1, 3, 7, 14, and 30 days, adjusted based on concept mastery:
> the higher your mastery score, the longer the next interval."

*Show the task cards. Point to the interval badges ('Day 1', 'Day 3').*

*Click 'Mark Done' on one task.*

> "Marking a task done updates the mastery score for that concept, removes this task,
> and automatically schedules the next review at the next interval."

*Show the toast notification '✓ Reviewed!'*

---

### 3:15 — Ask Buddy + Voice (30 s)

**[Navigate to Ask Buddy]**

> "Ask Buddy is a multi-turn chatbot. I can select a material to ground it in my own content,
> or ask general questions."

*Select Python Programming Fundamentals from the dropdown.*

*Type: "What is the difference between a list and a tuple in Python?"*

> "The answer is grounded in my material context. Follow-up suggestions appear as chips below."

*Click one of the follow-up suggestion chips.*

**[Enable auto-speak toggle 🔊]** *(Chrome only)*

> "Voice mode uses the browser's Speech Synthesis API behind a `BaseSpeechService` abstraction —
> the same pattern as the LLM layer, so we can swap in IBM Watson Text-to-Speech without
> changing any page code."

*Ask a short question by mic button (🎤).*

---

### 3:45 — IBM watsonx.ai Switch (15 s)

**[Show .env.example or terminal briefly]**

> "The whole app works in demo mode with no credentials.
> To switch to IBM watsonx.ai — which is what we'd use in production —
> it's one line in `.env`: `LLM_PROVIDER=watsonx`.
> Every service, every API route, every page continues working identically
> because nothing in the codebase knows which LLM is behind the interface."

---

### 4:00 — Close

**[Return to Dashboard]**

> "Study Buddy shows how IBM watsonx.ai can be the intelligence layer behind a real, structured
> learning tool — not just a chat wrapper, but something that ingests content, extracts knowledge,
> generates assessments, and keeps students on track with evidence-based spaced repetition.
> Built in IBM Bob, end to end."

## Fallback Notes

- **If voice doesn't work**: Chrome only; HTTPS or localhost required. Fall back to typed input.
- **If processing is slow**: Use pre-seeded materials (run `python seed.py` — instant, no LLM calls).
- **If API is down**: Open `http://localhost:8000/docs` to show the live Swagger UI with all 16 endpoints.
- **If watsonx credentials are available**: set `LLM_PROVIDER=watsonx` in `.env` and restart the backend — nothing else changes.
